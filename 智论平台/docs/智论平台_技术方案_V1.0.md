## 第一篇 技术架构

### 第1章 技术架构总览

#### 1.1 技术架构设计原则

- **云服务优先**：所有AI能力通过API调用，零GPU服务器投入
- **微服务架构**：模块解耦，独立部署，弹性扩展
- **弹性扩展**：按需扩缩容，应对流量波动
- **安全合规**：数据加密、访问控制、审计日志

#### 1.2 技术栈选型

| 层级 | 技术选型 | 云服务 | 说明 |
|-----|---------|-------|------|
| 前端 | Next.js 14 + TypeScript | Vercel | SSR支持SEO |
| 后端 | Node.js + Fastify | 阿里云函数计算 | 轻量高效 |
| 数据库 | PostgreSQL + Redis | 阿里云RDS | 托管免运维 |
| 向量库 | pgvector | RDS插件 | 无需额外服务 |
| 对象存储 | MinIO API | 阿里云OSS | 文档图片存储 |
| AI模型 | 多API聚合 | DeepSeek/硅基流动/Azure | 按token计费 |

#### 1.3 系统架构

五层架构设计：

- **接入层**：CDN、API Gateway、负载均衡
- **应用层**：前端应用、后端服务
- **服务层**：AI服务、引用服务、图表服务、存储服务
- **数据层**：关系数据库、向量数据库、缓存、对象存储
- **基础设施层**：云服务、监控、日志

### 第2章 核心技术模块

#### 2.1 AI论文去重模块

技术原理：基于语义理解的文本改写，保留原意的同时降低重复率。

- 分句分词：中文分词、句子边界识别
- 语义理解：BERT嵌入、语义相似度计算
- 改写生成：同义替换、句式重组、段落重构
- 降重率预估：基于检测算法模拟

对应产品方案第3.1章

#### 2.2 AIGC降痕模块

检测原理：基于perplexity（困惑度）和burstiness（突发性）分析。

- Perplexity分析：AI生成文本困惑度较低
- Burstiness分析：AI生成文本句式更均匀
- 对抗改写：引入随机性、增加句式变化
- 多轮优化：迭代改写直到检测率达标

对应产品方案第3.1章

#### 2.3 知识库RAG模块

RAG（检索增强生成）架构：

- 文档解析：PDF/Word解析、OCR识别
- 分块策略：按段落/按语义分块
- 向量化：BGE-M3嵌入模型
- 索引存储：pgvector向量索引
- 检索增强：相似度检索 + LLM生成

对应产品方案第3.2章

#### 2.4 图表生成模块

| 图表类型 | 生成方式 | 技术栈 |
|---------|---------|--------|
| 流程图 | AI生成 + 模板 | Mermaid/Draw.io |
| 架构图 | AI生成 + 模板 | Mermaid/PlantUML |
| CAD图 | AI生成 + 导入 | DXF解析 |
| 统计图 | 数据导入生成 | ECharts/AntV |
| 思维导图 | AI生成 + 手动编辑 | 自定义SVG |

对应产品方案第3.3章

#### 2.5 引用格式引擎

三层架构设计：

- **数据层**：文献元数据存储（PostgreSQL）
- **规则层**：格式模板与条件逻辑（可配置）
- **渲染层**：引文生成与格式化

对应产品方案第5章

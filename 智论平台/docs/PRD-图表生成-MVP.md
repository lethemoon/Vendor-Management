## 1. 功能概述

### 1.1 功能定位

图表生成是智论平台P0核心功能，定位为**面向中文学术场景的全域数据可视化引擎**。该功能独立于已完成的论文降重、AIGC检测与降痕、知识库引用管理功能，专注于解决用户在使用平台各功能模块过程中产生的数据可视化需求——将枯燥的数字和文字转化为直观、美观、可交互的图表。

**核心定位差异（vs 已有功能）：**
- 论文降重：解决与已有文献的重复率问题（输出：重复率数值+标红片段）
- AIGC检测/降痕：解决AI生成文本的识别和优化问题（输出：AIGC率+段落热力图）
- 知识库与引用管理：解决文献信息管理和引用格式规范问题（输出：文献列表+引用字符串）
- **图表生成（本功能）：为以上所有功能及用户行为数据提供可视化呈现层**

**一句话定位**：图表生成是智论平台的"数据之眼"，让每一项功能的结果都能被看见、被理解、被传播。

### 1.2 目标用户

| 用户群体 | 核心需求 | 使用频率 | 付费意愿 |
|---------|---------|---------|---------|
| 本科毕业生 | 毕业论文AIGC检测报告中的风险分布图 + 参考文献类型统计图 | 高（毕业季） | 中 |
| 硕士研究生 | 多轮优化趋势追踪 + 知识库文献增长分析 + 写作进度仪表盘 | 中高 | 高 |
| 博士研究生 | 引用关系网络图 + 关键词共现分析 + 功能使用雷达图 | 高 | 高 |
| 高校教师 | 学生作业批量检测统计面板 + 字数消耗分析 | 低 | 低 |
| 平台运营者 | 用户行为数据分析 + 功能使用趋势监控 | 高 | N/A（内部使用） |

**典型用户画像：**
- 李同学，22岁，大四学生，刚完成AIGC检测，看到满屏的数字和文字段落感到困惑，希望能有一张饼图直观展示自己论文的风险等级分布，以及一张趋势线图了解多轮优化后的AIGC率变化
- 张博士，27岁，研二学生，知识库里已经积累了80多篇文献，想知道这些文献的类型分布是什么样子的，每个月新增了多少篇，哪种引用格式用得最多
- 王教授，45岁，高校教师，需要查看班级30名学生的论文检测情况汇总，希望有一个仪表盘能一目了然地看到整体情况

### 1.3 核心价值主张

**解决的痛点：**
1. **数据密恐症**：平台各功能产生大量结构化数据（AIGC率、段落数、字数、引用数等），纯文本/表格展示难以快速理解
2. **报告缺乏说服力**：学生向导师汇报论文修改进展时，仅有数字不够直观，需要可视化佐证
3. **写作进度不可见**：用户在撰写长篇论文时，不知道自己的写作节奏是否合理，各章节完成度如何
4. **知识库管理盲目**：积累了大量文献但不知道分布特征，无法发现研究领域的知识图谱
5. **平台黏性不足**：缺少吸引回访的数据概览页面，用户用完即走

**带来的价值：**
1. **一图胜千言**：将检测结果、优化历程、文献统计等数据转化为直观图表，降低认知负担
2. **专业报告感**：生成的图表可直接截图用于学术报告、答辩PPT、导师沟通等场景
3. **写作全景透视**：通过仪表盘实时掌握论文写作进度、资源消耗、功能使用情况
4. **知识发现辅助**：通过引用网络图、关键词共现矩阵等高级可视化辅助学术洞察
5. **平台差异化**：国内学术工具中罕见的专业级数据可视化能力，形成竞争壁垒

## 2. 用户故事

### 2.0 主用户故事（全局）

**作为** 一名正在使用智论平台进行学术论文写作的高校学生，

**我希望** 在使用AIGC检测、知识库管理、论文编辑等功能时，系统能够自动生成专业的数据可视化图表（包括饼图、柱状图、折线图、热力图、网络图等），帮助我直观理解检测结果、追踪优化趋势、分析文献构成、掌握写作进度，

**以便于** 我能够更高效地做出决策（如哪些段落需要重点改写）、更自信地向导师展示工作进展、更科学地管理我的学术写作全过程。

**验收标准 (AC)：**

- **AC-1: 图表自动渲染**
  - Given 用户已完成一次AIGC检测或拥有知识库数据
  - When 用户进入对应的结果页或统计页
  - Then 页面应在2秒内自动渲染出对应的可视化图表，无需手动触发

- **AC-2: 图表交互性**
  - When 用户鼠标悬停在图表的数据点上
  - Then 应显示详细的Tooltip信息（具体数值、占比、时间戳等）
  - And 点击数据点可跳转到对应的详情页或执行筛选操作

- **AC-3: 响应式适配**
  - When 用户在不同尺寸的设备上访问（桌面端≥1280px / 平板端768-1279px / 移动端<768px）
  - Then 所有图表应正确适配屏幕宽度，保持可读性和可操作性

- **AC-4: 导出与分享**
  - When 用户对某张图表满意并希望用于报告
  - Then 应提供一键导出为PNG/SVG图片的功能
  - And 导出的图片应包含完整的标题、图例和数据标签

- **AC-5: 性能体验**
  - When 页面同时渲染5张以上的图表
  - Then 首屏渲染时间应≤3秒
  - And 图表切换/更新动画流畅（≥60fps）

### 2.1 场景①：AIGC检测可视化（Recharts为主）

#### 故事1-1：风险等级分布饼图 (RiskPieChart)

- **优先级**：P0-Must have
- **所属场景**：AIGC检测可视化
- **技术选型**：Recharts PieChart
- **故事内容**：

**As a** 刚完成AIGC检测的用户，
**I want** 通过一个饼图直观地看到我论文中各风险等级段落的数量分布（低/中/中高/高风险各占多少），
**So that** 我可以快速判断整篇论文的整体风险状况，决定是否需要进行全面改写。

**验收标准：**

- **Given** 用户完成了一次AIGC检测，检测结果包含15个段落，其中低风险3个、中风险5个、中高风险4个、高风险3个
- **When** 用户进入检测结果页面 `/aigc/result/:id` 的概览区域
- **Then** 系统应渲染一个环形饼图（Donut Chart），包含以下要素：
  - 四个扇区分别对应 low(🟢)、medium(🟡)、medium-high(🟠)、high(🔴)
  - 每个扇区显示百分比占比和绝对数量（如 "中风险 33% (5段)"）
  - 中心空洞显示总体AIGC率（如 "65%"）
  - 风险等级颜色与平台现有AIGC检测页面的颜色体系一致
  - 图表下方显示图例（Legend），支持点击图例项隐藏/显示对应扇区

- **Given** 所有段落均为低风险（AIGC率<20%）
- **When** 渲染饼图
- **Then** 饼图应仅显示绿色扇区，中心显示"✅ 安全"标识
- **And** 可选显示鼓励文案："您的论文AIGC风险很低，继续保持！"

- **Given** 所有段落均为高风险（AIGC率>70%）
- **When** 渲染饼图
- **Then** 饼图应仅显示红色扇区，中心显示"⚠️ 高危"标识
- **And** 可选显示建议文案："建议立即开始降痕处理"

**数据格式要求：**

```typescript
interface RiskPieChartData {
  segments: Array<{
    riskLevel: 'low' | 'medium' | 'medium-high' | 'high';
    count: number;
    percentage: number;
    color: string;           // 如 #22c55e, #eab308, #f97316, #ef4444
    label: string;           // 如 "低风险", "中风险", "中高风险", "高风险"
  }>;
  totalParagraphs: number;
  overallScore: number;      // 总体AIGC率 0-100
}
```

**Done定义：**
- [ ] 饼图能根据检测结果数据正确渲染四色扇区
- [ ] 百分比计算精确到小数点后1位
- [ ] 中心文字动态显示总体AIGC率
- [ ] hover时扇区微微外扩（explode效果）并显示tooltip
- [ ] Legend可交互（点击隐藏/显示）
- [ ] 无数据时显示空状态占位符
- [ ] 响应式布局下最小宽度不小于280px

#### 故事1-2：段落风险热力图 (ParagraphHeatmap)

- **优先级**：P0-Must have
- **所属场景**：AIGC检测可视化
- **技术选型**：Recharts BarChart（水平条形图 + 自定义颜色编码）
- **故事内容**：

**As a** 正在查看AIGC检测结果的用户，
**I want** 以条形图的形式逐段展示每个段落的AIGC疑似度，并用颜色深浅表示风险高低（红色=高风险），
**So that** 我可以一眼看出哪些段落最危险，点击后直接进入该段落的改写流程。

**验收标准：**

- **Given** 检测结果包含12个段落，疑似度分别为 [25, 18, 78, 45, 62, 33, 82, 55, 28, 71, 39, 20]
- **When** 用户查看段落热力图区域
- **Then** 系统应渲染一个水平条形图：
  - Y轴：段落编号（P1-P12）
  - X轴：疑似度评分（0-100）
  - 每个条形的填充颜色根据分数动态映射：
    - 0-20: `#bbf7d0` (green-200)
    - 21-40: `#fef08a` (yellow-200)
    - 41-60: `#fed7aa` (orange-200)
    - 61-80: `#fecaca` (red-200)
    - 81-100: `#fca5a5` (red-300)
  - 条形右侧显示具体数值标签
  - 条形按段落序号从上到下排列（P1在最上方）
  - 图表高度自适应（每段约36px高度，最多显示全部段落）

- **Given** 用户将鼠标悬停在P3段落（疑似度78%）的条形上
- **Then** Tooltip应显示：
  ```
  📄 第3段落
  AIGC疑似度: 78%
  风险等级: 🔴 高风险
  问题类型: 句式单一, 用词模式化
  字数: 203字
  ```

- **Given** 用户点击了P7段落（疑似度82%）的条形
- **Then** 系统：
  - 高亮该条形（加粗边框+阴影效果）
  - 自动滚动页面到下方的"段落详情与改写区"
  - 在段落选择器中自动勾选P7
  - URL参数可选追加 `?highlight=p7`

- **Given** 检测结果的段落数超过20段
- **When** 渲染热力图
- **Then** 图表区域应：
  - 显示虚拟滚动（仅渲染可视区域内的条形）
  - 提供搜索/筛选框（按风险等级过滤）
  - 支持排序切换（按序号/按疑似度降序/升序）

**数据格式要求：**

```typescript
interface ParagraphHeatmapData {
  paragraphs: Array<{
    index: number;             // 段落序号 1-N
    score: number;             // 疑似度 0-100
    riskLevel: string;
    wordCount: number;
    issues: string[];          // 问题类型数组
    preview: string;           // 前50字符预览
    color: string;             // 计算后的颜色值
  }>;
  sortBy: 'index' | 'score_asc' | 'score_desc';
  filterBy: 'all' | 'low' | 'medium' | 'medium-high' | 'high';
}
```

**Done定义：**
- [ ] 条形颜色根据分数正确映射到5档色彩
- [ ] 数值标签右对齐显示在条形末端
- [ ] Tooltip信息完整且排版清晰
- [ ] 点击条形可联动下方详情区
- [ ] >20段时启用虚拟滚动，无卡顿
- [ ] 排序和筛选功能正常工作
- [ ] 与AIGC检测页面的现有热力图组件视觉风格统一

#### 故事1-3：多轮优化趋势折线图 (OptimizationTrendLine)

- **优先级**：P0-Must have
- **所属场景**：AIGC检测可视化
- **技术选型**：Recharts LineChart
- **故事内容**：

**As a** 进行过多轮AIGC降痕优化的用户，
**I want** 通过一条折线图看到每次优化后AIGC率的变化趋势，
**So that** 我可以评估优化的效果，判断是否继续优化或已达目标。

**验收标准：**

- **Given** 用户进行了4轮优化，AIGC率变化轨迹为：初始65% → 第1轮42% → 第2轮28% → 第3轮18% → 第4轮12%
- **When** 用户查看优化历史时间线区域的趋势图
- **Then** 系统应渲染一个折线图：
  - X轴：优化轮次（初始 → R1 → R2 → R3 → R4）
  - Y轴：AIGC疑似率（0-100%）
  - 折线连接各数据点，带平滑曲线（monotone curve）
  - 每个数据点显示圆形标记（radius=5）
  - 数据点旁标注具体数值
  - 折线下方填充渐变色（从主题色到透明，opacity=0.1）
  - 安全阈值线（20%）以虚线形式标注在Y轴对应位置
  - 当前值位置有脉冲动画效果（吸引注意力）

- **Given** 用户hover到第2轮的数据点（28%）
- **Then** Tooltip显示：
  ```
  📊 第2轮优化
  AIGC率: 28%
  较上一轮: -14% ↓
  操作: 改写段落 P3, P7, P9
  时间: 2026-05-09 10:42:15
  ```

- **Given** 当前AIGC率为12%，低于安全阈值20%
- **When** 渲染趋势图
- **Then** 图表底部应显示达标标记："✅ 已达安全目标 (<20%)"

- **Given** 用户只完成了初始检测，尚未进行任何优化
- **When** 渲染趋势图
- **Then** 图表应显示单点状态（仅初始值），并提示"开始优化后将显示趋势变化"

- **Given** AIGC率在某轮出现反弹（如从25%上升到32%）
- **When** 渲染该数据点的标记
- **Then** 该数据点应以特殊颜色（橙色）标注，Tooltip中显示"⚠️ 率值回升"警告

**数据格式要求：**

```typescript
interface OptimizationTrendData {
  points: Array<{
    roundLabel: string;          // "初始", "R1", "R2", ...
    roundNumber: number;         // 0=初始, 1=第1轮, ...
    score: number;
    changeFromPrevious: number | null;  // null表示初始点
    timestamp: string;
    actions?: string;            // 操作摘要
    isRebound: boolean;          // 是否反弹
  }>;
  safeThreshold: number;         // 默认20
  targetAchieved: boolean;
}
```

**Done定义：**
- [ ] 折线平滑连接所有数据点
- [ ] 安全阈值虚线正确标注在Y轴20%位置
- [ ] 区域填充渐变色自然过渡
- [ ] 反弹数据点特殊高亮
- [ ] 单点状态（仅初始检测）优雅降级
- [ ] 达标/未达标状态明确标识
- [ ] Tooltip信息丰富且格式规范

#### 故事1-4：改写版本对比柱状图 (VersionCompareBar)

- **优先级**：P0-Must have
- **所属场景**：AIGC检测可视化
- **技术选型**：Recharts BarChart（分组柱状图）
- **故事内容**：

**As a** 正在选择改写版本的用户，
**I want** 通过分组柱状图对比原始版本与三个改写版本（保守/平衡/激进）在各维度的预估AIGC率，
**So that** 我可以直观比较各版本的改写力度，选择最适合的方案。

**验收标准：**

- **Given** 用户选中了一个高风险段落（原始AIGC率78%），系统生成了3个改写版本
- **When** 用户在改写版本选择区域查看对比图
- **Then** 系统应渲染一个分组柱状图：
  - X轴：评估维度（总体AIGC率、句式多样性、词汇丰富度、语义保持度）
  - Y轴：得分（0-100）
  - 每个维度有4根柱子：原始(灰色) / 保守型(蓝色) / 平衡型(紫色) / 激进型(橙色)
  - 柱子顶部显示数值标签
  - hover时高亮当前维度下的所有柱子
  - 推荐版本（通常为平衡型）的柱子带有星标★

- **Given** 各版本数据如下：
  - 原始：AIGC率78% / 句式多样性35 / 词汇丰富度40 / 语义保持度100

| 单张图表首次渲染 | ≤800ms | ≥60(动画期) / 0(静态) | ≤15MB | 含数据请求+DOM渲染 |
| 4张图表并发渲染 | ≤2000ms | ≥30(动画期) | ≤50MB | 统计页首页加载 |
| 图表交互响应(hover) | ≤50ms | ≥60 | 不变 | Tooltip显示延迟 |
| 图表数据更新(过渡动画) | ≤300ms | ≥60 | 不变 | 新数据到达时的重绘 |
| 图表PNG导出 | ≤1500ms | N/A | 峰值≤80MB | html-to-image渲染 |
| 大数据量图表(>100数据点) | ≤1500ms | ≥30(动画期) | ≤30MB | 热力图/趋势图 |
| 空数据/加载态渲染 | ≤100ms | ≥60 | ≤5MB | Skeleton/EmptyState |
| 移动端图表渲染 | ≤1200ms | ≥30 | ≤25MB | 弱网环境考虑 |

**性能优化策略：**

1. **前端渲染优化**：
   - Recharts: 利用 `isAnimationActive={false}` 在低端设备关闭动画
   - ECharts: 使用 `progressive` 渐进式渲染（>1000数据点时）
   - 虚拟滚动：热力图>30条时启用 `react-window`
   - 图表懒加载：Intersection Observer 监听视口，离屏图表延迟渲染
   - Memo优化：图表组件使用 `React.memo` 避免不必要的重绘

2. **数据请求优化**：
   - API数据聚合在后端完成，前端只做渲染
   - 图表数据缓存：SWR/stale-while-revalidate策略（TTL=5分钟）
   - 并行请求：同一页面的多个图表数据并行获取（Promise.all）
   - 增量更新：仅拉取变化的数据字段（非全量替换）

3. **打包体积控制**：
   ```json
   // 目标打包体积
   {
     "@recharts/recharts": "~150KB (gzipped)",
     "echarts": "~300KB (gzipped, 按需引入)",
     "echarts-for-react": "~5KB (gzipped)",
     "html-to-image": "~20KB (gzipped)"
   }
   ```
   - ECharts按需引入：仅注册实际使用的组件（graph/heatmap/gauge/radar）
   - Tree-shaking：确保未使用的图表类型不打入包内
   - 动态import：ECharts相关组件使用 `next/dynamic` 懒加载

### 7.2 技术债务 knowingly incurred

| 技术债务 | MVP做法 | 后续改进 | 风险等级 |
|---------|--------|---------|---------|
| **图表主题硬编码** | 前端常量定义主题色 | 后端主题API+用户自定义 | 低 |
| **PNG导出客户端渲染** | html-to-image浏览器端渲染 | 服务端Puppeteer渲染（更可靠） | 低 |
| **无图表CDN加速** | 图表随SPA打包加载 | 独立微前端/CDN分发 | 低 |
| **ECharts完全排除** | Phase 1 仅用 Recharts | Phase 2 按需引入 ECharts | 无（设计如此） |
| **无图表AB测试** | 固定一种图表设计方案 | 多方案AB测试+数据驱动选型 | 低 |
| **缓存无主动失效** | TTL过期被动刷新 | 数据变更时主动清除缓存 | 低 |
| **无图表性能监控** | 仅依赖APM整体监控 | 专门图表渲染性能埋点 | 低 |

### 7.3 范围蔓延防护

1. **图表数量锁死**：MVP严格限定8张图表（4+4），不允许新增
2. **交互复杂度限制**：每张图表的核心交互不超过3种（hover/click/filter）
3. **ECharts延后**：任何提议使用ECharts的需求一律推迟到Phase 2
4. **导出格式锁死**：MVP仅支持PNG，SVG/PDF/EPS推迟
5. **定制化锁死**：不允许用户自定义图表配色/字体/布局（Phase 2再考虑）

### C. 技术选型对比备忘

| 维度 | Recharts | ECharts | 推荐 |
|-----|---------|---------|------|
| React集成度 | ⭐⭐⭐⭐⭐ 原生React组件 | ⭐⭐⭐ 需要封装层 | Recharts |
| 学习曲线 | ⭐⭐⭐⭐⭐ 简单声明式 | ⭐⭐ 复杂配置对象 | Recharts |
| 图表丰富度 | ⭐⭐⭐ 基础统计图表齐全 | ⭐⭐⭐⭐⭐ 含网络图/热力图/地图等 | ECharts |
| 定制灵活性 | ⭐⭐⭐ 受限于组件API | ⭐⭐⭐⭐⭐ 完全可控 | ECharts |
| Bundle Size | ⭐⭐⭐⭐ ~150KB gzip | ⭐⭐ ~300KB gzip(按需引入) | Recharts |
| 性能(大数据量) | ⭐⭐⭐ 中等 | ⭐⭐⭐⭐ progressive渲染 | ECharts |
| 社区活跃度 | ⭐⭐⭐⭐ 活跃 | ⭐⭐⭐⭐⭐ 非常活跃 | 持平 |
| 文档质量 | ⭐⭐⭐⭐ 清晰 | ⭐⭐⭐⭐⭐ 非常详尽 | ECharts |
| 适用场景 | 统计报表/Dashboard | 复杂可视化/探索性分析 | 按需选择 |

**选型结论**：
- **MVP (Phase 1)**：全面采用 Recharts，满足8张统计图表需求
- **Phase 2**：引入 ECharts 覆盖网络图/热力图/雷达图/仪表盘等复杂可视化
- **混合策略**：通过 ChartProvider 统一封装两层图表库的差异，对外暴露统一的 props 接口
